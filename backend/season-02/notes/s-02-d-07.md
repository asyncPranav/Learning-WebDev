# MongoDB / Mongoose Notes

### 1. Fields Not Defined in the Schema

By default, **Mongoose ignores fields that are not defined in the schema** when creating or updating a document.

For example, if the schema is:

```js
const userSchema = new mongoose.Schema({
  name: String,
  email: String,
});
```

and the request body contains:

```js
{
  name: "Rahul",
  email: "rahul@example.com",
  age: 25
}
```

Since `age` is not defined in the schema, Mongoose will **not save it** by default.

> **Note:** This behavior depends on the schema's `strict` option. The default is `strict: true`.

---

### 2. `findById()` Internally Uses an ID Query

Mongoose's:

```js
User.findById(userId)
```

is essentially shorthand for:

```js
User.findOne({ _id: userId })
```

So:

```js
User.findById("123...")
```

is equivalent to:

```js
User.findOne({ _id: "123..." })
```

The important point is that `findById()` specifically searches using the document's **`_id`** field.

---

### 3. Query Methods Accept Options

Many Mongoose query methods allow us to pass an **options object** to modify how the query behaves or what it returns. Read more on mongoose docs to know more options.

For example:

```js
User.findByIdAndUpdate(
  userId,
  { name: "Rahul" },
  { new: true }
);
```

Here:

```js
{ new: true }
```

is an option that tells Mongoose to return the **updated document** instead of the document from before the update.

Without `new: true`:

```js
User.findByIdAndUpdate(userId, { name: "Rahul" });
```

Mongoose returns the **old version** of the document by default.


---


### Common Pattern

```js
const user = await User.findByIdAndUpdate(
  req.params.userId,
  req.body,
  {
    new: true,
  }
);
```

Here:

* `req.params.userId` → identifies the document
* `req.body` → contains the fields to update
* `new: true` → returns the document **after** the update
