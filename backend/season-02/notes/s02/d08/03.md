For this case, I recommend using a **destructured object** rather than passing the entire `req.body`.

Why? It makes it explicit which fields you want to update and prevents accidental updates to protected fields.

Since your allowed fields are:

* `age`
* `skills`
* `about`
* `photoUrl`

Use this:

```js
// Update /user/:userId - update allowed user fields
app.patch("/user/:userId", async (req, res) => {
  try {
    const { age, skills, about, photoUrl } = req.body;

    const user = await User.findByIdAndUpdate(
      req.params.userId,
      { age, skills, about, photoUrl },
      {
        new: true,
        runValidators: true,
      },
    );

    if (!user) {
      return res.status(404).json({
        success: false,
        message: "User not found",
      });
    }

    return res.status(200).json({
      success: true,
      message: "User updated successfully",
      user,
    });
  } catch (error) {
    return res.status(500).json({
      success: false,
      message: "Error updating user",
      error: error.message,
    });
  }
});
```

### But there is one important issue ⚠️

With the above code, if you send only:

```json
{
  "age": 22
}
```

then `skills`, `about`, and `photoUrl` become `undefined` in the update object. Depending on how Mongoose handles the update, this isn't the cleanest approach for a PATCH endpoint.

A better version is to **build the update object only from fields that were actually provided**:

```js
// Update /user/:userId - update allowed user fields
app.patch("/user/:userId", async (req, res) => {
  try {
    const { age, skills, about, photoUrl } = req.body;

    const updateData = {};

    if (age !== undefined) updateData.age = age;
    if (skills !== undefined) updateData.skills = skills;
    if (about !== undefined) updateData.about = about;
    if (photoUrl !== undefined) updateData.photoUrl = photoUrl;

    const user = await User.findByIdAndUpdate(
      req.params.userId,
      updateData,
      {
        new: true,
        runValidators: true,
      },
    );

    if (!user) {
      return res.status(404).json({
        success: false,
        message: "User not found",
      });
    }

    return res.status(200).json({
      success: true,
      message: "User updated successfully",
      user,
    });
  } catch (error) {
    return res.status(500).json({
      success: false,
      message: "Error updating user",
      error: error.message,
    });
  }
});
```

### Why I prefer this for our DevTinder project

Think of it like this:

```js
req.body
```

means:

> "Whatever the client sends, try to update it."

Whereas:

```js
const { age, skills, about, photoUrl } = req.body;
```

means:

> "I, the backend developer, explicitly decide what the client is allowed to update."

So **use destructuring + an explicit update object**.

Later, when we add authentication and authorization, we'll also make sure the logged-in user can modify **only their own profile**, not someone else's.
