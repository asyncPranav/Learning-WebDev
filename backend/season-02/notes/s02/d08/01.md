## Mongoose Schema Validation — Quick Notes

### 1. `required`

Field must be provided.

```js
name: {
  type: String,
  required: true
}
```

---

### 2. `type`

Defines the data type.

```js
age: Number
email: String
isActive: Boolean
skills: [String]
```

Common types:

```text
String, Number, Boolean, Date, Array, ObjectId, Buffer, Mixed, Map
```

---

### 3. `enum`

Allows only specific values.

```js
gender: {
  type: String,
  enum: ["Male", "Female", "Other"]
}
```

---

### 4. `min / max`

For numbers.

```js
age: {
  type: Number,
  min: 18,
  max: 100
}
```

---

### 5. `minLength / maxLength`

For strings.

```js
username: {
  type: String,
  minLength: 3,
  maxLength: 20
}
```

---

### 6. `match`

Validates a string using a regular expression.

```js
email: {
  type: String,
  match: /^[^\s@]+@[^\s@]+\.[^\s@]+$/
}
```

---

### 7. `trim`

Removes whitespace from the beginning and end.

```js
username: {
  type: String,
  trim: true
}
```

```text
"  rahul  " → "rahul"
```

---

### 8. `lowercase`

Converts string to lowercase.

```js
username: {
  type: String,
  lowercase: true
}
```

```text
"RaHuL" → "rahul"
```

---

### 9. `uppercase`

Converts string to uppercase.

```js
code: {
  type: String,
  uppercase: true
}
```

- This distinction is worth remembering:
  - `enum`, `min`, `match`, `validate` → validation
  - `trim`, `lowercase`, `uppercase` → transform/normalize the value

---

### 10. `default`

Sets a value when one isn't provided.

```js
about: {
  type: String,
  default: ""
}
```

Can also be a function:

```js
createdAt: {
  type: Date,
  default: Date.now
}
```

---

### 11. `unique`

Creates a **unique index**.

```js
email: {
  type: String,
  unique: true
}
```

⚠️ `unique` is **not a Mongoose validator**. It relies on MongoDB's unique index, so duplicate values produce a MongoDB duplicate-key error.

---

### 12. Custom Validator

For your own validation logic:

- for age validation
```js
age: {
  type: Number,
  validate: {
    validator: function (value) {
      return value >= 18;
    },
    message: "Age must be at least 18"
  }
}
```

- for gender validation
```js
gender: {
  type: String,
  required: true,
  validate: {
    validator: function (value) {
      return ["male", "female", "other"].includes(value);
    },
    message: "Invalid gender"
  }
}
```

Another valid syntax
Mongoose also supports a function directly:

```js
gender: {
  type: String,
  required: true,
  validate: function (value) {
    if (!["male", "female", "other"].includes(value)) {
      throw new Error("Invalid gender");
    }
  }
}
```

---

# Doubt
They are **equivalent** in this case. Both are valid Mongoose syntax.

### 1. Method shorthand

```js
gender: {
  type: String,
  required: true,
  validate(value) {
    if (!["male", "female", "other"].includes(value)) {
      throw new Error("Invalid gender");
    }
  }
}
```

### 2. `function` syntax

```js
gender: {
  type: String,
  required: true,
  validate: function (value) {
    if (!["male", "female", "other"].includes(value)) {
      throw new Error("Invalid gender");
    }
  }
}
```

### Why does `validate(value) {}` work?

It's just JavaScript **method shorthand**:

```js
const obj = {
  validate(value) {
    // ...
  }
};
```

is essentially the same as:

```js
const obj = {
  validate: function (value) {
    // ...
  }
};
```

So for Mongoose, you can use either.

**Recommendation:** Use the shorter method syntax for readability:

```js
gender: {
  type: String,
  required: true,
  validate(value) {
    if (!["male", "female", "other"].includes(value)) {
      throw new Error("Invalid gender");
    }
  }
}
```

But for this particular case, I'd use `enum` instead.

### One Important Point: Validation on Updates

Mongoose validation behaves differently when updating documents.

For example:

```js
User.findByIdAndUpdate(
  userId,
  { age: 15 },
  { new: true }
);
````

By default, Mongoose **does not run schema validators on update operations**.

If you want validators to run during the update, use `runValidators: true`:

```js
User.findByIdAndUpdate(
  userId,
  { age: 15 },
  {
    new: true,
    runValidators: true
  }
);
```

* `new: true` → returns the **updated document**
* `runValidators: true` → runs Mongoose **schema validation** during the update

> **Important:** Remember `runValidators: true` whenever you want schema validation to apply to update operations such as `findByIdAndUpdate()`.

### One More Important Distinction

Think of Mongoose schema options in these categories:

```text
Validation
├── required
├── enum
├── min / max
├── minLength / maxLength
├── match
└── validate

Transformation / Normalization
├── trim
├── lowercase
└── uppercase

Database / Index Behavior
└── unique

Default Value
└── default
```

### Quick Memory

```text
Validation      → Is the value allowed?
Transformation  → How should the value be stored?
Unique          → Can duplicate values exist?
Default         → What value should be used if none is provided?
```


---
### Most important ones to remember

```text
required  → must exist
type      → data type
enum      → allowed values
min/max   → number range
minLength/maxLength → string length
match     → regex validation
trim      → remove surrounding spaces
lowercase → convert to lowercase
uppercase → convert to uppercase
default   → default value
unique    → unique database index
validate  → custom validation
```

**Remember:** Mongoose schema validation is mainly about **protecting the integrity of your stored data**.

## `match`

`match` validates a **String** using a Regular Expression (Regex).

```js
email: {
  type: String,
  match: [
    /^[^\s@]+@[^\s@]+\.[^\s@]+$/,
    "Please provide a valid email"
  ]
}
````

### Syntax

```js
match: [regex, "error message"]
```

* First value → Regex used for validation
* Second value → Error message if validation fails

Example:

```js
username: {
  type: String,
  match: [
    /^[a-z0-9_]+$/,
    "Username can only contain lowercase letters, numbers, and underscores"
  ]
}
```

> `match` is mainly used for **String pattern validation**.

---

# Custom Error Messages

Many Mongoose validators allow an **array** containing:

```text
[validation rule, error message]
```

Example:

```js
age: {
  type: Number,
  min: [18, "Age must be at least 18"]
}
```

```js
username: {
  type: String,
  minlength: [3, "Username must be at least 3 characters"],
  maxlength: [30, "Username cannot exceed 30 characters"]
}
```

### `required` with a custom message

`required` also supports an array:

```js
name: {
  type: String,
  required: [true, "Name is required"]
}
```

Here:

```text
true              → validation rule
"Name is required" → error message
```

---

# `{VALUE}` in Error Messages

Mongoose provides special placeholders that can be used in validator messages.

`{VALUE}` is replaced with the **actual value that failed validation**.

Example:

```js
gender: {
  type: String,
  enum: {
    values: ["Male", "Female", "Other"],
    message: "{VALUE} is not a valid gender"
  }
}
```

If the user sends:

```js
{
  gender: "Unknown"
}
```

The error message will be approximately:

```text
"Unknown is not a valid gender"
```

So:

```text
{VALUE}
↓
actual value provided by the user
```
