## Validator.js vs Express-Validator

The main difference is:

> **Validator.js validates individual values.**
> **Express-validator validates data coming from Express requests.**

---

| Feature                  | Validator.js               | Express-validator         |
| ------------------------ | -------------------------- | ------------------------- |
| Main purpose             | Validate strings/values    | Validate Express requests |
| Used with                | Any JavaScript application | Express.js                |
| `req.body` integration   | Manual                     | Built-in                  |
| `req.params` integration | Manual                     | Built-in                  |
| `req.query` integration  | Manual                     | Built-in                  |
| Middleware               | ❌                          | ✅                         |
| Error collection         | You handle it              | Built-in                  |
| Email validation         | `validator.isEmail()`      | `body("email").isEmail()` |
| URL validation           | `validator.isURL()`        | `body("url").isURL()`     |

---

# 1. Validator.js

You manually validate a value.

```js id="vjdumr"
const validator = require("validator");

const email = req.body.email;

if (!validator.isEmail(email)) {
  return res.status(400).json({
    message: "Invalid email",
  });
}
```

### Flow

```text id="iepepg"
req.body.email
      ↓
validator.isEmail()
      ↓
true / false
      ↓
You manually handle the error
```

You can use it inside Mongoose:

```js id="49l84s"
email: {
  type: String,
  validate(value) {
    return validator.isEmail(value);
  },
}
```

---

# 2. Express-validator

Express-validator works as **Express middleware**.

```js id="qyp6b7"
const { body, validationResult } = require("express-validator");

app.post(
  "/user",
  body("email").isEmail().withMessage("Invalid email"),
  (req, res) => {
    const errors = validationResult(req);

    if (!errors.isEmpty()) {
      return res.status(400).json({
        errors: errors.array(),
      });
    }

    // Continue creating user
  },
);
```

### Flow

```text id="auxtoj"
Request
   ↓
express-validator middleware
   ↓
Validates req.body
   ↓
Stores validation errors
   ↓
validationResult(req)
   ↓
Continue or return errors
```

# Example: Email Validation

### Validator.js

```js id="ur8bov"
if (!validator.isEmail(req.body.email)) {
  return res.status(400).json({
    message: "Invalid email",
  });
}
```

You check the result yourself.

### Express-validator

```js id="zltc5l"
body("email").isEmail()
```

Then:

```js id="bjppoe"
const errors = validationResult(req);
```

Express-validator collects errors for you.

---

# Important relationship

**Express-validator uses validator.js internally for many validations.**

Conceptually:

```text id="puh6dx"
Express Request
     ↓
Express-validator
     ↓
Validator.js functions
```

So express-validator provides a convenient layer around validation for Express applications.

---

# Which one should you use?

### Use Validator.js when:

* You are validating inside a Mongoose schema.
* You need to validate a single value.
* You want simple manual validation.
* You are not necessarily using Express.

```js id="cc1t4j"
validator.isEmail(email);
validator.isURL(url);
```

### Use Express-validator when:

* You are building an Express API.
* You want request validation middleware.
* You want to validate `body`, `params`, and `query`.
* You want structured validation errors.

```js id="ub2p2u"
body("email").isEmail();
param("userId").isMongoId();
query("page").isInt();
```

## Best practice for your Express + Mongoose application

You can use **both**:

```text id="xrf5vf"
Client Request
      ↓
Express-validator
(validates incoming request)
      ↓
Controller / Route
      ↓
Mongoose Schema + Validator.js
(validates data before database)
      ↓
MongoDB
```

### Simple recommendation

* **Learning/basic project:** Mongoose + Validator.js is enough.
* **Production Express API:** Express-validator + Mongoose validation is a stronger approach.
